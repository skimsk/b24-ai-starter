# Приложения 1ДАА для Битрикс24 Маркетплейса: правила и чеклист публикации

Этот файл можно положить в корень нового проекта приложения как `CLAUDE.md`. Им пользуется агент `b24-app-builder` (`.claude/agents/b24-app-builder.md`). Рядом лежат два файла с подробностями:

- [image-style.md](image-style.md): иконка и кадры для карточки.
- [media-upload.md](media-upload.md): как загрузить картинки в кабинет.

Отвечай Антону по-русски, коротко и по делу.

## Где что лежит

- Код: iMac, `~/Documents/b24app/<app>`. Новое приложение делаем копией ближайшего готового (например, `short_pause` или `client_time`). Git локальный, коммитим после каждого шага.
- Основа: стартер `b24-ai-starter`. Фронтенд на Nuxt 4 с компонентами `@bitrix24/b24ui-nuxt` (B24*) работает в iframe портала. Бэкенд на Django (Python) с воркером. Всё собирается через Docker Compose и `makefile`.
- Прежде чем коммитить, прогоняй линт, сборку и проверку стиля `b24-app-ui`.

## Сервер и деплой

- Сервер 1daa.ru, за Caddy. Каждое приложение лежит в `/opt/<app>` и работает в своих контейнерах `<prefix>-db`, `-api`, `-worker`, `-frontend` на своих портах. В Caddy под него заводится путь `https://1daa.ru/<app>/`.
- Деплой: `make push-server`. Изменения на сервере вносим только после «да» Антона.
- `.env` на сервере генерируется заново: пароль БД, ключи JWT и Django, ключ шифрования. client_id и client_secret берутся из кабинета через MCP b24. Секреты не попадают в чат, git и память.
- Облачная сессия не ходит на сервер по SSH, команды выполняются на Mac через Remote Control.

## Кабинет вендора (MCP b24)

- Для одного приложения заводим ровно один черновик. Дальше только обновляем его, второй не создаём.
- Код приложения начинается с префикса аккаунта: `degtyaryov.<имя_через_подчёркивание>`, например `degtyaryov.client_time`. Префикс `1daa.` кабинет не принимает.
- Адреса: обработчик `https://1daa.ru/<app>/`, установка `https://1daa.ru/<app>/install`.
- Обязательный язык только `ru`. Нужны: название, menuName, short (до 60 символов), full, installInstruction, support, eula, privacy, keywords (до 2000 символов), иконка и скриншоты.
- Постоянные ссылки:
  - EULA: <https://1daa.ru/distribution-integration/license/>
  - Политика: <https://1daa.ru/distribution-integration/privacy/>
  - Контакты: <https://1daa.ru/kontakty/>
- Для каждого права в `scopeJustification` пиши, зачем оно нужно. `crm` проверка помечает как широкое, поэтому объясни его подробно.
- Порядок проверок: `apps_precheck`, затем один запуск `apps_ai_precheck_run` после последней правки (у него дневной лимит), затем раз в 30 секунд `apps_ai_precheck`. На модерацию (`apps_submit`) отправляем только после явного «да» Антона.

## Что ловит ИИ-проверка (уроки «Звонок вовремя», 2026-11-25)

- Бренд пишется только «Битрикс24 Маркетплейс». «Маркет», «маркет Битрикс» и т.п. проверка считает нарушением.
- Права запрашивай минимальные. Если нужен только текущий пользователь (часовой пояс, проверка админа через `user.admin`, `profile`), ставь `user_brief`, а не `user`. Обоснование прав (`scopeJustification`) кабинет принимает только при `user_basic`/`user` — при `user_brief` поле не сохраняется, и это нормально.
- Перед сменой права проверь код: какие `user.*` вызывает приложение. Объяви то же право в `.env`/README.
- Инструкция по установке должна честно описывать, зачем каждое право. Не пиши того, чего код не делает.
- Обещания совпадают везде: срок ответа поддержки («обычно за 15 минут») одинаковый в тексте support и на кадре «Поддержка».
- Технический сбой проверки по лицензии или скриншотам не блокирует отправку: эти поля проверит модератор.

## Чеклист публикации

1. Приложение задеплоено, `https://1daa.ru/<app>/` и `/install` отвечают 200.
2. В карточке заполнено: код `degtyaryov.…`, название, menuName, short, full, установка, поддержка, ссылки EULA и политики, ключевые слова, категории и теги, changelog версии, права и встройки.
3. Иконка 650 и 10 кадров загружены через сайт кабинета (см. [media-upload.md](media-upload.md)).
4. `apps_precheck`: всё зелёное, кроме ИИ-проверки.
5. Один запуск `apps_ai_precheck_run`, затем чтение `apps_ai_precheck`. Исправляешь замечания и запускаешь снова. Лимит 5 запусков в день.
6. Когда `apps_precheck` показывает `canSubmit: true`, спрашиваешь Антона. Только после его «да» выполняется `apps_submit` с idempotencyKey.
7. После отправки: `apps_autotest` раз в несколько минут, затем `moderation_get_status`. Замечания модератора исправляешь и отправляешь снова.

## Тексты карточки (BBCode)

- full:
  - вступление `[p]…[/p]`;
  - блоки `[b]Когда пригодится[/b]`, `[b]Что вы получаете[/b]` (списком `[list][*][b]Фича.[/b] пояснение`), `[b]Первый результат[/b]` (`[list=1]`, 3 шага), `[b]Условия и ограничения[/b]`, `[b]Вопросы и ответы[/b]`;
  - в конце курсивом оговорка про товарные знаки.
- support: «Поддержка работает круглосуточно, 24/7. Отвечают люди, а не бот, ответ обычно приходит за 15 минут…». Дальше: чем поможем, «доработки по запросу делаем бесплатно», «Пишите прямо из приложения: раздел «Поддержка»», затем почта, телефон и сайт списком. Обещания в тексте и на кадре «Поддержка» должны совпадать.
- installInstruction: нумерованные шаги, какие права запросит приложение и зачем, что приложение само создаёт при установке, плюс кнопка «Проверить и восстановить».

## Интерфейс приложения

- Только компоненты B24*. Разделы: «Обзор», «Настройки» (подвкладки с белыми карточками и переключателями, как в «Зависимых полях» и «Точка банк»), «Помощь» (как в «Точка банк»), «Поддержка» (статус, карточки тем, поле сообщения с вложениями; обращения сохраняются в БД).
- Шрифт Manrope, кнопки — скруглённые прямоугольники. Текст 14 px, подписи 12–13 px, заголовки блоков 16 px, заголовок страницы 24 px. Фон поля в карточке CRM `#f6fafb`.
- В картинках и примерах не должно быть реальных данных клиентов.
