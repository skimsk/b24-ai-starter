# Модульбанк

Подключение Модульбанка к приложению. Банковская часть заменена, всё остальное
(сопоставление со сделками и счетами, уведомления, вкладки CRM) общее с Точкой:
операции Модульбанка сохраняются в ту же таблицу `tochka_payments`.

## Как клиент подключает банк

1. В личном кабинете Модульбанка: Настройки → API → создать ключ с правами
   `account-info` и `operation-history`.
2. В мастере установки (шаг «Подключение», `setup/StepConnect.vue`) вставить ключ.
   Сервер проверяет его запросом `account-info` и сохраняет подключение
   (`modulbank_credentials`). Стор `tochka.ts` (общий для интерфейса) ходит
   в `/api/modulbank/*` за статусом, счетами, остатками и синхронизацией.
3. Чтобы платежи приходили сразу, вставить в ЛК Модульбанка адрес уведомлений,
   который показывает приложение: `/api/modulbank/webhook/<ключ портала>`.

Кнопка «Попробовать на тестовых данных» подключает песочницу банка
(заголовок `sandbox: on`, токен `sandboxtoken`).

OAuth для Маркета появится после регистрации приложения в Модульбанке
(письмо на api@modulbank.ru): токен, полученный по OAuth, пойдёт в тот же клиент.

## API приложения

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/modulbank/status` | статус подключения, компания, адрес вебхука, время последней синхронизации |
| POST | `/api/modulbank/connect` | `{"apiToken": "..."}` или `{"sandbox": true}` |
| POST | `/api/modulbank/disconnect` | отключить и стереть ключ |
| GET | `/api/modulbank/accounts` | счета с остатками |
| POST | `/api/modulbank/sync` | `{"days": 30}` или `{"startDate", "endDate"}` |
| POST | `/api/modulbank/webhook/<key>` | уведомление банка; подпись `SHA1Hash` = sha1(первые 10 символов ключа + "&" + id операции) |

## Фоновая синхронизация

```
* * * * * /usr/bin/flock -n /var/lock/modulbank-sync.lock docker exec api python manage.py sync_modulbank_background --days 2
```

Интервал и включение берутся из тех же настроек портала, что у Точки.

## Что синхронизируется

- Счета `CheckingAccount` и `CardAccount`, кроме закрытых и удалённых. Транзитный
  счёт пропускается, иначе поступление посчиталось бы дважды.
- Операции, кроме `RejectByBank` и `Canceled`. `Debet` — поступление
  (`credit_debit = credit`), `Credit` — списание.
- Время операций в API без зоны, считаем его московским.

## Платёжные ссылки (интернет-эквайринг)

Протокол взят из официальных плагинов банка (github.com/modulbank-pay):
POST-форма на `https://pay.modulbank.ru/pay/`, уведомление на `callback_url`,
статус `GET /api/v1/transaction/`, возврат `POST /api/v1/refund`. Подпись — двойной
sha1 от секретного ключа и строки `key=base64(value)` по алфавиту.

- Доступы: Merchant ID и секретный ключ из ЛК эквайринга Модульбанка (не ключ API
  выписки). Вводятся в Настройки → Эквайринг, есть тестовый режим.
- Ссылка ведёт на `/api/modulbank/pay/<id>`: страница сразу отправляет подписанную
  форму в банк. После оплаты банк возвращает покупателя на `/pay/<id>/done`.
- Уведомление банка: `/api/modulbank/acquiring/callback`. Проверяются подпись,
  merchant, сумма, валюта и тестовый флаг; оплата отмечается в общей таблице
  ссылок, дальше работают сверка с выпиской, поля CRM и уведомления.
- Эндпоинты `/api/modulbank/acquiring/{settings,retailers,payment-links,refresh-statuses}`
  и `/operations/<id>/refund` отдают тот же формат, что и у Точки.
- Способы оплаты: карта и СБП. T-Pay и «Долями» Модульбанк не поддерживает,
  в окне создания ссылки они скрыты.
- Фискальные чеки (`receipt_items`) пока не передаются.

## Что не проверено

Эквайринг: формат `order_id` (у нас UUID операции) и поле способа оплаты в уведомлении
нужно проверить на тестовых доступах банка.


Официальная документация api.modulbank.ru из облачной среды разработки не
открылась. Форматы запросов и ответов взяты из открытых клиентов API
(включая пример уведомления, подпись которого совпала с токеном песочницы).
До выката проверить на песочнице и на реальном ключе.
